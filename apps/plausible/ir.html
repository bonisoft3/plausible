The Answer Set — engineering design

Compiled from brief.md (pinned above) by the studio team, onto the mecha cluster, the omnishell terminal, the sayt loop and the bayt build graph.

Overview

A web-analytics dashboard over a checked-in log, whose correctness is decided by an oracle that never read its code: hand-authored SQL over the same 1 200 hits, plus the vendor’s own asserted numbers transcribed from its test suite. The app exists to mature the language, and the way it does that is by being gradeable — every number on every screen answers a published question, and every published question is asked of the app by something that runs.

Every entity takes the tab path (decision-01), which is the load-bearing decision rather than a shortcut: the aggregation has to live where a fixture harness can execute it, and at this tier that is the data-on-mutation seat (decision-02). Two reduces sit in it. stitch turns the log into visits and local hours from the log alone; rollup turns one cursor row into every figure, bucket, tick, path string, panel row and chip on the screen.

The idea worth carrying up is the second one: a route parameter reaches arithmetic without a write. Eleven cursors are materialised, each named by a URL, and the reduce reads exactly one of them through a read attribute. So there is no overlay, no precedence branch and no discriminator to go stale — and the cost, which is real, is that the answerable set is finite and the parameter is unlintable at this tier (decision-10, decision-20).

Entities

Event — tab

The log. 1 200 hits, eight columns, sorted by (epoch, id), and the one artifact three readers share: this app seeds it, oracle.sql reads the same file through read_json_auto, and the sidecar was written from it. Seeded and never written — nothing anywhere in this app writes to the log, and no screen offers to.

interactive is the hit’s own column and never a reading of its name: a custom event may declare itself non-interactive and then clears no bounce (decision-06).

Zone — tab

The site’s clock as three integer rows. A reduce has no Date and no Intl, and the terminal’s only formatter is pinned to UTC — so a local day is arithmetic over the row with the greatest starts_epoch at or before the instant, and never a rendered string (decision-04). Three rows are enough because the log spans one clock change.

Session — tab, written by stitch

The visit. Its id is <visitor>#<ord> because a reduce has no post: it may only write where it can name the key, so a visit’s identity has to be arithmetic over the log rather than a counter (decision-03).

Five of these columns are the ones two implementations most easily read differently, and each is a rule rather than a convenience: the boundary is the integer 1860; the entry page is the first page viewed; the duration runs to the last non-engagement hit; a visit bounces iff it viewed at most one page and carried no interactive hit that was not a page view; and the attribution is frozen at the first hit (decision-06).

pages and names are delimiter-fenced sets so a containment test cannot match across two of them. rollup answers a page slot about a VISIT from that column rather than by re-deriving the partition, which is what keeps one sessionization in the app.

SessionHour — tab, written by stitch

One row per visit per local hour it was open in. This is the whole of why the hourly visit counts do not sum to the day’s figure: at hour granularity a visit is counted in every hour it spanned, while visitors and page views are counted over hits. The asymmetry is graded rather than hidden (decision-08).

It is also what makes the spring-forward day twenty-three buckets rather than twenty-four with a hole: the walk steps to the next local hour boundary, and the hour the calendar skips is never a key.

Corpus — tab, written by stitch

The signal, not the summary. Its figures are what the front door shows, but its job is the wake: stitch states this row LAST, so a corpus write means every Session and SessionHour row of this world has already landed, and rollup’s second ear rides exactly that edge (decision-09). Seeded with one row of zeroes, because a root region whose row is missing poses empty for the whole screen.

Fold — tab, two rows

Each reduce’s own row, and the seam a refusal comes out of. There is no store-side predicate at this tier to put a validation in — the platform has three Jessie roles and none of them is a validator, and a refusal is a NonRetriableError off a mutation round trip a browser-tier collection never makes. So the writer guards its own writes, and a violation becomes ONE update patching error and no sink write at all (decision-12).

Returned, never thrown: a reduce’s writes ARE its return value, so a throw loses them and the error is never written.

FilterSet — tab, eleven rows, written by nothing

The DECLARED cursor: what a URL means. Eleven rows because eleven different shapes is what changes the arithmetic — a twelfth value of an existing shape changes nothing. Its id IS the :preset route parameter, which is what makes the answerable set finite and enumerated (decision-10).

The last two shapes exist because a cursor slot no graded number depends on is a fossil: without entry-page and goal, a rollup that never reads f_entry_page or f_name would produce byte-identical output on every assertion in the apparatus.

active_bucket is carried here as well as on the live cursor, because a reset binds every cursor column off this row and a column the reset cannot name is a column a reset cannot restore. It is seeded to the first point for the same reason every form that moves the window states it: a window holding fewer points than the last one has no row where the caret was standing.

Filter — tab, eleven rows, written by forms

The LIVE cursor: what the reader has done to it. Eleven rows, each seeded identical to its declared twin, and the only table any form writes. rollup reads exactly one of them, through data-read-cursor, so there is no overlay, no composition and therefore no precedence branch inside the reduce (decision-10).

Two tables rather than one singleton plus a discriminator, because a discriminator is a branch and a stale discriminator is a silently dead picker. Eleven independent cursors also means drilling on one preset cannot move another, and tab durability means no earlier visit’s drill-down leaks into a fresh one.

Topline — tab, one row, written by rollup

The divisors AND the displays, side by side. A wrong divisor cannot hide behind a quotient that rounds the same, so sessions_n, bounce_denom, pv_sum and dur_sum are graded columns rather than intermediates (decision-07).

The three quotients ship a _text column beside their numbers because the ROUNDING is part of the metric definition and the graded artifact is the rendered string. Only bounce_rate restricts its divisor: under a page filter bounce_denom counts the visits that ENTERED a matching page, while sessions_n counts the visits that matched at all.

It is one row and its region is a leaf slot, which is why it must be seeded: a slot with no row binds nothing and, decisively, does not fire.

Bucket — tab, written by rollup

b-00…b-27. Twenty-eight is the largest bucket count any legal pair produces (28d at day granularity), and the bound is stated as that maximum rather than as a round number.

A bucket exists for every grid step the window intersects, whether or not a hit falls in it: the grid is window arithmetic, never a group-by over the data, and it is walked on the site’s clock. That is what gives the day the clock changed twenty-three hour buckets, and a Sunday-start week the wrong count — which is why the four wrong readings are caught as CARDINALITY and not as arithmetic.

Scale — tab, one row, written by rollup

The chart, as two strings. path_d is one closed column per bucket, computed by the fold and bound onto an authored <svg viewBox="0 0 1000 300"> inside a LEAF SLOT — the one region kind that binds attributes and texts without sweeping its children, so the element is stamped once for the life of the visit (decision-14).

Nothing in this tree has a bound d yet, which is why the check that pins it is written before the chart is.

It carries the caret too, and that is where the caret’s arrows are bound. A region pinned on the point the caret is on is one the terminal clears the bindings of the moment the window stops holding that point — the filter placeholder stands there unresolved and the forms write nothing, with no error anywhere. This row is written on every pass, so what the arrows read is the one row that cannot go away, and its read interpolates nothing so no gesture re-hydrates it.

Breakdown — tab, written by rollup

One row per value per panel, keyed <panel>|<value>. ord is the row’s place under visitors desc, dim_value asc, and it is graded: ranked by page views instead of visitors a panel shows a DIFFERENT set of nine in a different order, and every number in it is still a number the oracle answers correctly. Selection and order are therefore on the oracle, not only the values (decision-11).

The five set_* columns are the whole cursor this row would write, with this panel’s slot replaced by this row’s value. They must be real columns for two independent reasons, and both are the platform’s: a nested item template binds against its OWN row, so {f_source} inside a breakdown item raises binding {f_source} not in row; and upsertBy PATCHES, so a form naming one slot would leave the other four standing and a reader would walk out of the graded space in one gesture (decision-13).

Chip — tab, written by rollup

One row per cursor slot in force. The id IS the slot name, because a click carries no payload — event.id is the row’s id and event.from is the nearest ancestor DOM id — so the row id has to be the datum. slot is declared unique so a per-slot region can be a SLOT at all: a slot’s filter must pin a pk, a unique field, or every column of a declared unique, and limit=1 is not a witness.

It carries the same five set_* columns as a Breakdown row, with its own slot emptied — a chip removal is the drill-down form run backwards.

Panel — tab, four rows

Four kinds of dimension, not four columns. on is the column that matters: it says whether the dimension is a property of the HIT or of the VISIT, and that decides both how a value is grouped and how a filter on it matches. It is what makes page and entry_page two different questions rather than two spellings of one — they disagree on every visit that reached a page without entering there.

Metric — tab, seven rows

The specification, as data. says is the published sentence, formula is the published expression verbatim, and reads is this app’s own wording of what it computes. They are three columns and they are rendered side by side, never merged: rewording the reading leaves the sentence alone, so a departure cannot be tidied away (decision-16). This is w3caria’s move, and it is the only rung in the apparatus that grades the READING rather than the arithmetic.

Three of the seven formulas are the vendor’s own ClickHouse expressions, transcribed character for character, and all four facts about a quotient — the zero-divisor answer, the rounding, and which divisor is conditional — are read off one expression each. It only works as a mitigation if nobody tidies it, which is why it is set as an identifier rather than as prose.

Range — tab, five rows

Three rolling ranges and two pinned, expressed without a second table: from_days_back and to_days_back are counted in LOCAL CIVIL DAYS back from the as-of day, and one boolean says whether the upper end is as_of itself.

back(midnight(as_of), k) is a subtraction of DATES and never of k × 86400 seconds. Across the clock change the two differ by an hour, and that hour holds a hit — which is why a window computed by multiplication gives 28d twenty-nine day buckets rather than twenty-eight. The fifth row is the only way a reader reaches the twenty-three-hour day on an hourly axis.

Question — tab, 312 rows

The published question set, one row each, thirteen columns. No row carries an expected value. A seeded expected value is a golden file, and a golden file is not an oracle — it grades the app against a number the same author wrote down while looking at the app. Every number comes from the ground truth at run time (decision-18).

departs is three words and each is a different kind of honesty: no is as published, approximates is something the sentence permits but does not require, and declined is a question this app does not answer at all with the cost in note. It is reflected as an attribute and styled, rather than being a data-when arm — an attribute plus CSS has neither the discriminant-default hazard nor a template per value.

The rows themselves are transcription and land with the specification screen; what this rung owes is the columns and the closed vocabularies above, which is what the coverage anti-joins read.

Screens

index — what the log is, and the eleven ways of asking about it

Reads: Corpus (filter id=eq.the) as the root list-of-one, which also carries stitch’s seat; and FilterSet (order pos.asc) for the eleven shapes, each a link to its own address. The corpus figures come from the fold, not from a count in the template: a template binds a column and cannot compute one.

Mutations: none. Every gesture here is a navigation (open-shape). keep: 1 — returning from a dashboard should return to where the reader was in the list.

dash — one cursor, and every number that follows from it

Reads: FilterSet (filter id=eq.{param.preset}) as the root list-of-one, which hands {range}, {grain} and every f_* to every child for free; then, nested inside its item template, Corpus twice — once carrying stitch’s seat and once carrying rollup’s corpus ear — and Filter (filter id=eq.{param.preset}) carrying rollup’s cursor ear. The display regions carry no seat at all: Topline and Scale and each per-slot Chip as leaf slots pinned on a pk or a declared unique, Tick, Bucket and four Breakdown regions as lists. They subscribe to their own tables and re-render when a reduce writes them, and that is the whole read path.

Mutations: two reduces at the data-on-mutation seat and forms for everything a reader does — there is no data-on-click reduce anywhere in this app, which removes the whole class of silently dead controls (decision-05). There is no data-machine either (decision-22), so the two pickers are forms over the live cursor row (pick-range, pick-grain); a drill-down is a form whose submit button is the row (drill-down), a chip removal is the same form with one slot emptied (remove-chip), and the reset restores the declared cursor (reset-cursor). strip: false and keep: 0: a parametrized route has no static href, and the first-run state is the point.

panel — one dimension, in full

Reads: the same three seat regions as dash, so the numbers on this screen are the same numbers computed by the same run; then Panel (filter id=eq.{param.panel}) as a nested list-of-one, and Breakdown (filter panel=eq.{id}, order ord.asc) inside its item template — where {id} interpolates the ENCLOSING row, which is the panel’s.

Mutations: none of its own; the seats write, and the only gesture is going back. One route with two parameters, which no route in this tree carries today: matchRoute splits pattern and path on / and fills every :name segment, and each is pinned by its own region’s data-filter so both are planned.

sessions — the stitch, shown

Reads: Corpus (filter id=eq.the) as the root list-of-one carrying stitch’s seat; Session (order start_epoch.asc,id.asc) inside it, rendering EVERY column; and SessionHour (filter session_id=eq.{id}, order ord.asc) nested inside each visit’s item template.

Mutations: the stitch seat, and nothing else. This screen is the no-test-only- surface property made concrete: the ground truth grades exactly the rows the app shows, which is also what stops a column becoming the fossil nothing lints.

log — the eight columns, and no control at all

Reads: Corpus (filter id=eq.the) as the root list-of-one carrying the stitch seat, and Event (order epoch.asc,id.asc) rendering every column of every hit.

Mutations: none, and none is possible: there is no form and no button on this page, so read-only is a property of the markup rather than a rule something has to enforce.

spec — the specification, as rows

Reads: Corpus as the root list-of-one carrying the stitch seat; Metric (order pos.asc) for the three columns; Range (order pos.asc) with Grain (filter range=eq.{id}) nested inside its item template, so the legal pairs are shown by the same rows the pickers obey; and Question (order departs.asc,id.asc) for the whole published set.

Mutations: none. departs is reflected as data-departs="{departs}" and styled, rather than being a data-when arm.

Handlers

stitch — the log becomes visits

Reads event, zone, session, session_hour, corpus, fold and writes session, then session_hour, then corpus — in that order, because applyUpdates batches only consecutive runs of the same op against the same collection, so the stated order is the written order and the corpus write is the signal the whole wake graph hangs on.

It recomputes absolutely and writes differentially, so a pass over an unchanged world writes nothing and therefore does not re-wake: the fixpoint is structural rather than counted. That second pass is not redundant — it is the executable proof that the fold is absolute.

graph LR E[event rows] --> S[partition by visitor] Z[zone rows] --> L[local hour walk] S --> V[gap at 1860 s] V --> W[session rows] L --> H[session_hour rows] W --> H H --> C[corpus, stated last]

rollup — one cursor row becomes every number on the screen

Reads the fourteen tables its seat declares plus the ONE cursor row data-read-cursor puts in state.rows.cursor, and writes topline, bucket, tick, scale, breakdown, chip. It computes only the active cursor position and deletes every row it did not recompute, which is what makes the write total and keeps the breakdown bounded.

It is live on none of its own sinks, so it never self-wakes and one run per input change is all it gets — which is only correct because the write is differential. A run where the cursor is not exactly one row is a broken precondition and raises.

Invariants & test pairs

The ground truth answers every graded position in ONE DuckDB invocation, with no precondition degraded: output.documents == 1 && output.violations == 0 && output.everyWrongReadingDiffers. Twenty-five preconditions raise rather than degrade, because a ground truth that quietly answers a narrower question than it was asked is worse than no ground truth — every assertion under it stays green while the thing being graded walks away.

The committed log is the artifact its sha names, and three independent sessionizations of it agree column for column: output.shaMatches && output.partitionsAgree && output.columnsAgree. The three are compared PAIRWISE inside one suite, so regenerating one of them cannot launder a break in another; and the vendor’s own asserted numbers reproduce over the transcribed cohorts before anything else runs.

Mounted cold with only the seed, the app stitches the log into exactly the visits DuckDB cuts it into: output.sessions == output.duckdbSessions && output.everyColumnAgrees, cardinality asserted BEFORE any column, so a missing visit fails as a missing visit. A visit that opened on something other than a page view has no entry page until it views one, a one-hit visit lasts zero seconds and stays in the divisor, and an interaction clears a bounce that a second page view would also have cleared.

The boundary is the integer 1860 and the four planted gaps walk it: output.visitsPerGap == [1, 1, 1, 2]. Not 1800, and not the phrase “thirty minutes”: the vendor’s own diff truncates to whole minutes, so 1859 s reads as 30 and continues while 1860 s reads as 31 and starts a new visit. A clone reading the sentence rather than the source gets this wrong and nothing else in the suite would say so.

A visit is materialized in every local hour it was open in, and the hour the clock skips is absent rather than empty: output.hoursOnDstDay == 23 && output.hourlyVisitsSum != output.dailyVisits. The inequality is the assertion, not a tolerance: the hourly visit counts are NOT supposed to sum to the day’s figure, and a suite that let them would be grading a different app.

Each of the five ranges resolves to the pair of integers the arithmetic states, walked as civil dates: output.windowSeconds == 1810800 && output.buckets == 103. The bucket total is the discriminator: a Sunday-start week, a window opened by multiplying 86 400, days cut in UTC and a 24-hour DST day each change one of the seven counts, so all four wrong readings are caught as cardinality rather than as arithmetic.

The six figures, their divisors and their rendered strings all agree with the ground truth, and only bounce rate restricts its divisor: output.agreesWithOracle && output.bounceDenom != output.sessionsN && output.bounceRateText == "0%". The unentered preset is the case that separates them: a page nobody entered on has visits above zero and a bounce rate of exactly zero, and both divisors are on the screen beside their quotients.

Each panel ranks by visitors descending with ties broken by the value ascending, the dashboard keeps the first nine and the full panel keeps them all: output.ordAgrees && output.dashboardRows <= 9 && output.fullPanelRows == output.oracleRows. The tie leg decides membership and not merely order — twenty-seven panels are tied across the ninth row — so ord is in the coverage key on both sides.

A drill-down submits all five slots, so the reachable cursor space is the graded one: output.slotsWritten == 5 && output.backToStart && output.presetsIndependent. Every position is reached by mounting the route and submitting the row’s own form, never by writing the cursor from the test — a test that writes the row directly grades a cursor no reader has.

The series is one column per bucket over one coordinate system, a bucket that measured nothing is a mark on the axis floor rather than a column of no height, every column is a row of the table beside it, and the arrows walk those rows one at a time: output.columns == output.points && output.floorMarks == output.emptyBuckets && output.ticks == 5 && output.tableRows == output.points && output.caretMarked == 1 && output.caretWraps == false. This one is written FIRST, because nothing in this tree has a bound d yet and because linkedom serializes a wrong-namespace element and a clipped-to-nothing element identically to a correct one — so every tier below a real browser passes on a blank chart. The caret leg walks past where a shorter axis reaches and then shortens the axis, which is the gesture both declined spellings break on (decision-23).

An incoherent derived row is refused as ONE update naming the clause, with no sink written: output.clausesNamed == 6 && output.sinkWrites == 0 && output.boundaryRowsPass. The two boundary rows — a bounce rate of exactly 0 and exactly 100 — must pass, and the arithmetic suite must stay RED for the arithmetic reason while the guard is firing: a guard that hides a wrong number is worse than no guard.

Every published question is driven through the app’s own forms and the number is read off the RENDERED TEXT rather than off the row: output.driven == 312 && output.readFromDom && output.saysAndReadsNeverMerged. Reading the DOM grades the binding and the rounding along with the arithmetic, which is the only way a metric whose definition includes its rounding can be graded at all.

The mechanical cross of the vocabularies is generated from the app’s OWN rows, never from a literal list in the test, and swept with cardinality asserted before value: output.cardinalityBeforeValue && output.networkRequests == 0. A literal list is a second copy of the vocabulary and it will drift; the zero is the offline claim, and it holds because the log and the arithmetic are both already in the tab.

Every anti-join closes: output.undriven == [] && output.ungraded == [] && output.unshown == [] && output.everySlotMovesANumber. The forward one finds a published question nothing drove; the reverse one finds a number the app renders that nothing grades, which is the app-level stand-in for a platform lint that does not exist; the unrendered one walks the graded space from the other side and finds a number the oracle answers that no screen showed (decision-21). The slot leg is what refuses a cursor column no graded number depends on.

Both appearances render, nothing animates, and every figure is set in a fixed advance: output.loopingAnimations == 0 && output.smallestTarget >= 24 && output.tabularFigures && output.horizontalOverflow == 0. No bar grows from zero, because two readings of the same number must look the same; the only motion in the app is the caret, and it arrives without travelling under reduced motion. The fourth is the one claim about the page rather than about an element on it: the document is never wider than the viewport at either width, so a sheet too wide for a phone scrolls inside its own box and the page does not slide under the reader. Every claim above can hold of every element while the page slides, which is why it is measured on the document.

Decisions

01 — everything is tab, and that is the load-bearing decision rather than a shortcut. No Postgres, no Electric, no conduit, no bloblang, no migration, no policy, no publication, no pipeline. The reason is the grader, not the size: a raw pipeline has no browser-tier form at all, and the only check any app in this tree declares over a bloblang mapping is a lint. For an app whose oracle IS arithmetic, putting the arithmetic in the one seat no fixture harness reaches destroys the grader before it is written. Nothing is at device either: a device collection persists across program versions and nothing backfills a new column, so a returning reader would get binding {x} not in row on a schema that is certain to move.

02 — the aggregation is two reduces at the mutation seat. That seat is the one an off-disk mount executes, so every graded assertion runs at the test verb with no cluster up. Two rather than one because they have different worlds and different wake conditions: stitch depends on the log and the clock alone and is cursor-independent, rollup depends on the cursor and would otherwise re-derive the partition on every gesture. Splitting them is also what lets the visits be graded against DuckDB BEFORE any aggregate is, which is the one place a shared misunderstanding of the sessionization would show.

03 — a visit’s id is arithmetic, because a reduce has no post. A reduce may only write where it can name the key, so <visitor>#<ord> is not a convenience: it is the only way a derived row can exist at all. The same constraint gives a session-hour <session_id>@<hour> and a breakdown row <panel>|<value>. It costs the freedom to key on anything the log does not already determine, and it buys the property that a recomputation lands on the same rows rather than beside them.

04 — the clock is three integer rows and a civil-from-days algorithm. A reduce is denied Date, and the terminal’s only formatter is pinned to UTC, so a local day cannot be a rendered string. It is a subtraction of DATES over the Zone row covering the instant, and never k × 86400 seconds — across the clock change the two differ by an hour and that hour holds a hit. The independent witness is DuckDB’s ICU: the ground truth asks a real tz database the same question and the two must agree.

05 — every mutation is a form and every derivation is a fold; there is no data-on-click reduce anywhere. That removes the whole class of silently dead controls: a handler one level above its region still resolves, so a control wired one tag too high is inert under the finger with no error anywhere. A form either submits or it does not. The cost is that a gesture cannot compute — which is why a breakdown row carries the five set_* columns it would write (decision-13).

06 — the five rules two implementations read differently are literals, not phrases. The boundary is the integer 1860 and appears as that integer in the fold, in the ground truth, in Metric.reads and in the test that walks it. Page views count only pageview; events count every hit except engagement. The entry page is the first page VIEWED. Duration runs to the last non-engagement hit. A bounce needs at most one page view AND no interactive non-pageview hit, read off the hit’s own column rather than off its name. “Thirty minutes” appears only in the published sentence, where it is a quotation and not a rule.

07 — the divisors are graded columns, not intermediates. sessions_n, bounce_denom, pv_sum and dur_sum sit beside the quotients they produce, and both are on the screen. Without them a wrong divisor hides behind a quotient that rounds the same, and the one case in the whole app where two metrics divide by DIFFERENT counts — bounce rate restricting its divisor to the visits that entered a matching page, while views per visit does not — would be invisible rather than demonstrated.

08 — the hourly visit counts do not sum to the day’s, and the screen says so rather than reconciling it. At hour granularity a visit is counted in every local hour it was open in, which is what SessionHour materialises, while visitors and page views are counted over hits. Two implementations can agree on every visit and still disagree here, so the asymmetry is stated in the ir, on the screen, and in an assertion that requires the two NOT to be equal. Presenting it as a sum would be the most plausible wrong app this brief admits.

09 — the wake graph closes on one edge, and the edge is a write order. A data-on-mutation seat wakes when its OWN region’s read changes and at no other time — data-reads fills the world and subscribes to nothing. So the second run of rollup, the one over a complete session set, exists only because stitch states corpus LAST and rollup keeps an ear on that row. Reordering those three writes silently gives rollup a partial world with no second wake to correct it, and every number would be zero with nothing red. Each mount settles at two runs of stitch and three of rollup; an assertion written to any other pair goes red on correct code.

10 — two cursor tables, and therefore no precedence branch. FilterSet is what a URL MEANS and is written by nothing; Filter is what the reader has done to it and is the only table a form writes. The reduce reads exactly one row of the second, through data-read-cursor="filter?id=eq.{param.preset}", so there is no overlay to compose and no discriminator to go stale — a discriminator is a branch, and a stale one is a silently dead picker. This is also how a route parameter reaches arithmetic without a write, which no app in this tree does today. It costs the ability to name a cursor the eleven rows do not materialise, and that cost is what makes the answerable set finite.

11 — a panel’s SELECTION and ORDER are graded, not only its numbers. Ranked by page views instead of visitors, the page panel shows a different set of nine in a different order — and every number in it is a number this oracle answers, and answers correctly. So ord is a real column on the oracle’s side and in the coverage key on both sides. The tie leg decides membership rather than merely order: twenty-seven panels are tied on visitors across the ninth row, so a fixture that lost its ties would silently weaken this.

12 — the coherence guard lives in the reduce, because there is no store-side predicate to put it in. The platform has exactly three Jessie roles and none is a validator; #Entity declares no validations field; and a tab entity could not reach one anyway, since a refusal is an error off a mutation round trip a browser-tier collection never makes. So the writer guards its own writes: it fails at the same moment, in the seat where it happened, and costs a call. What is genuinely lost is a FORM’s write — the cursor is form-written and ungated, so a malformed cursor is caught by arithmetic rather than refused at the door. That is the honest cost, and it is what the platform is being asked for.

13 — a drill-down writes every slot, not one. upsertBy PATCHES an existing row with only the submitted fields, so a form carrying one f_* would leave the other four standing and a reader would reach a two-slot cursor no question grades — in one gesture, silently. Hence five set_* columns per breakdown and chip row, submitted together. They have to be real columns rather than bindings reached upward, because a nested item template binds against its own row and nothing else is in scope there.

14 — the chart is a leaf slot, and that is the design’s one real bet. A list region sweeps its markup on every refresh, so an authored element inside one cannot survive; a slot binds attributes and texts without sweeping, and across a root refresh the root’s item node is keyed by row id and survives, so the nested slot is re-stated rather than re-hydrated. <svg> in HTML content is the parser’s own breakout into foreign content, and d is neither a region attribute nor a URL attribute, so it takes the plain interpolate path. Nothing in this tree has a bound d yet, which is why the check that pins it is written before the chart is.

15 — every geometry number is a fold-computed column, never a string out of the log. The axis positions, the bar shares and the bounce arcs all ride custom properties, and nothing validates that channel: a value carrying its own ; is a second declaration nobody wrote. So each is an integer column with a stated range, which also puts the picture’s geometry on the oracle — the arc is graded like any other number.

16 — the citation and the claim are different columns. says is the published sentence and formula the published expression; reads is what this app actually computes. They sit in adjacent cells and are never merged, so rewording the app’s reading to match the specification would be a diff on a column that is supposed to be a quotation. Three of the seven formulas are the vendor’s own expressions transcribed character for character, and four separate facts — the zero-divisor answer, three roundings, and which divisor is conditional — are read off them rather than restated.

17 — which granularities a range allows is rows, not a guard. The seven legal pairs are Grain rows, and the granularity buttons come from a nested region filtered on the live range. An illegal pair is therefore not merely hidden: its button does not exist, so no transition names it and nothing has to refuse it. A rule inside a handler is not a coverage axis; rows are, and the coverage anti-join can ask whether every one of the seven was driven.

18 — no question row carries an expected value. A seeded expected value is a golden file, and a golden file grades the app against a number the same author wrote down while looking at the app. Every number comes from the ground truth at run time. The one class of number this author did not compute — the vendor’s own asserted values over transcribed cohorts — is not a question row either: those are assertions on the GROUND TRUTH, checked before the app is asked anything, because a ground truth that disagrees with the vendor is wrong regardless of what the app does.

19 — no auth, and the cost is stated. Nothing here is per-person: the log is a checked-in artifact rather than anybody’s traffic, and there is no second reader to keep apart from the first. Declining it costs the two things a real analytics product needs most — a site is somebody’s, and a dashboard is shared — and neither is approximable at this tier: they need the cluster, a passkey and row policies, which is a different app and not a bigger local store. Scoped out rather than faked.

20 — escape hatches: none, and one platform hole named instead. No container, no WASM unit, no vendored component, no external endpoint. The two pieces of app code are reduces in the terminal’s own compartment, with window, document, fetch, eval, Date and Math.random all denied. The hole worth naming is the other way round: a browser-tier route parameter is UNLINTABLE, because the visual battery resolves a parameter by fetching its planned table over PostgREST and an all-tab app has no such table. Both parametrized routes come back unresolved, each a major finding, and the route is dropped from the live set — so the battery stays green and photographs neither. Reading that green as coverage is the mistake; the two routes are opened by hand instead, once each, with the console open.

21 — the graded space is walked from BOTH sides, because one side is half an oracle. The reverse anti-join walks the numbers the app RENDERED, so it can only fire on something a screen showed: an app that shows nothing, or drops a whole panel, or cuts a panel to its top three rows, produces no finding anywhere in it. The forward anti-join does not close that gap either — it grades the question ROSTER and never sees a rendered or a graded position at all. So a third anti-join walks the oracle’s own answers and asks which of them no screen showed, and the gap it closes is measured rather than argued: before it existed, deleting an entire panel produced zero findings. There is no declined region on that side, because what the oracle chose to answer is exactly what some screen owes.

22 — there is no data-machine anywhere, and that is a finding rather than a preference. A chart narrows a transition as click@<dom-id> and the wiring lint resolves that id as a LITERAL, so no chart can answer a button generated from rows. “The legal pairs are rows” (decision-17) and “the transitions are narrowed to affordances” are therefore mutually exclusive at this tier, and only one of them can be had. The rows win: an illegal pair has no button to narrow to, and every gesture on the dashboard is a form like every other mutation in the app. What it costs is the platform’s own machines check, which walks every arrow of every emitted chart against XState — a whole check the app forfeits, stated here rather than left as an absence.

23 — the caret rides the chart’s singleton, not the point it is on. Two platform walls, one shape. data-rove would put the tabstop on the point row, and the terminal counts a row on its way out: the one gesture that shortens the axis past the caret leaves the departing row reading true beside the arriving one, and the refresh throws a set has one current member on correct app code. A region pinned on that point fails the other way — when the window stops holding it the terminal clears the region’s bindings, so the filter placeholder stands there unresolved while the forms write nothing, with no error anywhere. So the readout is the ONE tabstop, it hangs on Scale at id=eq.the whose read interpolates nothing, and the walk is caret_prev and caret_next off that row; the point rows carry on_caret as an ordinary bound attribute, where a stale true on a node about to vanish is a stale class and nothing more. aria-activedescendant is APG’s other focus model and the one this reaches. Both walls were found by performing them.
